# Ch.25 — 전자 제출(eCTD): 구조, 의무 날짜, 어디로 보내나, 잘못 내면 어떻게 되나

> **덱:** Ch25_1(개념·구조) + Ch25_2(세부·상황형), 40장. 이틀 분량 한 장.
> **검증 메모(2026-11-22):** FDA eCTD 의무 NDA·ANDA·BLA **2017-05-05**, 상업 IND·DMF(Type III 제외) **2018-05-05**, Type III DMF **2019-05-05**; CDISC **2016-12-17**(신청)/**2017-12-17**(IND) 이후 시작 시험; EU eSubmission Roadmap CP 2010 → DCP 신규 2015-07-01 → MRP 신규 2017-01-01 → DCP/MRP 전체 2018-01-01 → NP 신규 2018-07-01 → NP 전체 2019-01-01; **eCTD v4.0** FDA 신규 수용 2024-09-16·forward compat 2026-10-16, EU CAP 선택 2025-12-22·권고 2027 Q1·의무 2028 Q1; **ESG NextGen USP** 2025-04-14; **E2B(R3)** IND 2026-04-01 / 시판 후 2026-10-01 — 두 덱 메모 기준. 745A(a), M8, Part 11, 지역 M1, EU 포털, PSUR Repository 2016-06, SPOR/IDMP는 ○. "?": 2253 eCTD 의무 연도.

## 학습 목표
1. eCTD의 네 개념(**sequence·leaf·lifecycle operation·STF**)과 v3.2.2 vs **v4.0**의 차이를 말한다.
2. 미국 **745A(a)** 의무 날짜·"not received" 논리·**CDISC**·**validation(high=거부)** 을 안다.
3. 미국·EU **Module 1** 구성과 **제출 통로**(ESG NextGen / E2B→FAERS; Gateway / CESP / PLM eAF / IRIS / EudraVigilance / CTIS / PSUR Repository / SPOR)를 짝짓는다.
4. **2026-09-01 기준** 의무·선택·미발효를 가른다.
5. **21 CFR Part 11** 요건과 2003 Scope guidance의 의미를 안다.

## 1. eCTD = CTD 구조 + XML 백본
ICH **M8**(v3.2.2; v4.0은 HL7 RPS)이 규정. 지역 **Module 1**(각 당국 사양) + 공통 **M2–M5**(M4). 네 개념:

| 개념 | 뜻 |
|---|---|
| **Sequence** | 제출 단위, **0000**부터 누적 |
| **Leaf** | 문서 1개(파일 + 제목 + 속성 + 체크섬) |
| **Lifecycle operation** | **new / replace / delete / append** — 이전 leaf와의 관계를 백본에 기록해 **current view** 생성; replace/delete는 modified-file 속성으로 대상 leaf 지정 |
| **STF**(study tagging file) | M4.2/M5.3 시험 문서를 시험 ID·문서 유형으로 묶는 XML — **FDA 요구**(EU 선택), 누락 = high severity |

CSR 정정본 → **replace**(이전은 superseded, current view에서 사라짐); 폐기 부록 → **delete**(이력엔 유지).

**v4.0**: v3.2.2는 문서 중심 백본(sequence마다 전체 구조 반복, 재사용 불가). v4.0은 **HL7 RPS 메시지** — **문서 재사용**, **keyword/controlled vocabulary**, **양방향 통신**, 그룹 제출. 2026-09 기준 **양쪽 다 v3.2.2가 표준**, v4.0은 선택.

## 2. 미국 — 의무, 거부, 데이터 표준
### 2.1 FD&C 745A(a) (FDASIA 2012 §1136)
guidance로 전자 형식을 **의무화**할 권한. 형식 미준수 제출은 **"제출되지 않은 것"** — filing 결함(RTF)이 아니라 **존재 요건**. 이유: 종이·혼합 제출은 심사 시스템에 들어올 수 없고, 강제엔 "접수 안 됨"이 가장 명확.

| 대상 | 의무일 |
|---|---|
| NDA · ANDA · BLA | **2017-05-05** |
| 상업 IND · DMF(Type III 제외) | **2018-05-05** |
| Type III DMF | **2019-05-05** |
| 비상업(research) IND | **면제**(전자 권장) |

### 2.2 Study data (CDISC)
**2016-12-17 이후 시작 시험**(NDA/BLA/ANDA), **2017-12-17 이후**(상업 IND) — SDTM(임상)·ADaM(분석)·SEND(비임상) + define.xml, reviewer's guide; 버전은 Data Standards Catalog.

### 2.3 Validation — high = 거부
**High**: 거부(미접수) — **filing/PDUFA 시계 미시작**, 같은 sequence 번호로 재제출(거부된 sequence는 존재하지 않는 것으로). 예: 백본 손상, 잘못된 application number, STF 누락. **Medium**: 접수되지만 지적, 다음 sequence에서 수정. 제출 전 FDA validation criteria 통과 + **pre-assigned application number** 요청이 표준.

### 2.4 제출 12주 전 체크
① granularity·leaf 제목 규칙(**Technical Conformance Guide**) ② Module 1 지역 문서 ③ STF·study data ④ PDF 규격(북마크·하이퍼링크·검색) ⑤ 내부 validation ⑥ **ESG NextGen** 계정·테스트 제출 ⑦ 수령 확인(ACK).

## 3. 미국 Module 1과 통로
### 3.1 US Module 1
| 섹션 | 내용 |
|---|---|
| **1.1** | forms **356h**, 3674 |
| 1.2 | cover letter |
| **1.3.3 / 1.3.4 / 1.3.5** | debarment 진술(FD&C 306(k)) / 재무 공개 **3454/3455**(21 CFR 54) / 특허 정보·certification(314.53) |
| 1.4 | references/LOA |
| 1.6 / 1.9 / 1.11 | meetings / pediatric / information amendment |
| **1.12.14** | 환경(Ch.11) |
| 1.13 | annual report |
| **1.14** | labeling — **SPL**(HL7 XML, DailyMed 원본; 라벨 변경마다 갱신) |
| **1.15** | promotional(**Form 2253**; AA 제품은 사전 제출 314.550/601.45; eCTD 의무 연도 확인 필요) |
| **1.16** | REMS |

**재무 공개(Part 54)**: 임계값 — ≥25,000 USD 지분, ≥25,000 USD 기타 보상, 특허권, 결과 연동 보상 → **3455**(공개 + 편향 최소화 설명), 미달은 **3454**(인증). 누락은 RTF 사유 가능.

**Grouped submission**: 한 sequence를 **복수 application number에 복제**(us-regional.xml에 모두 기재) — 내용 동일 조건, 신청별 lifecycle은 독립.

### 3.2 어디로 보내나
| 제출 | 통로 |
|---|---|
| IND(상업)·NDA·ANDA·BLA·DMF·보충·annual report·2253·REMS·IND safety report | **eCTD → ESG NextGen**(2025-04-14 USP가 WebTrader 대체; AS2 병행) |
| 시판 후 ICSR | **E2B(R3) → FAERS**(IND 전자 ICSR 2026-04-01~, 시판 후 2026-10-01~ = 기준일 이후) |
| 백신 ICSR | VAERS |
| 비eCTD(research IND, 일부) | CDER NextGen Portal |

**CBER도 동일** — eCTD + ESG NextGen, validation criteria 공통(일부 CBER 항목), pre-assigned number 경로·일부 양식만 다름.

### 4.2 포털 — 이름과 용도
| 시스템 | 용도 |
|---|---|
| **EMA eSubmission Gateway / Web Client** | CAP 제출(MAA·variation·PSUR 등) |
| **CESP** | 국가 당국(DCP/MRP/NP) 제출 |
| **PLM Portal – eAF** | 웹 신청서(MAA·variation) — **SPOR 마스터데이터 참조**, 구조화 데이터 + PDF |
| **IRIS** | orphan 지정·scientific advice·PRIME 등 절차 |
| **EudraVigilance** | ICSR(E2B(R3)) |
| **CTIS** | 임상시험 |
| **EudraGMDP** | GMP/GDP 인증·비준수 |
| **PSUR Repository** | 모든 PSUR(CAP·NAP) — **2016-06-13부터 의무**; CESP 제출은 PSUR로 인정 안 됨 |
| **SPOR**(IDMP) | **RMS** 참조어 · **OMS** 조직 · **PMS** 제품 · **SMS** 물질 |

짝짓기: CAP Type II variation → Gateway + eAF / 8개국 DCP MAA → CESP / orphan 지정 → IRIS / 중대 ICSR → EudraVigilance / Phase 2 CTA → CTIS / NAP PSUR → PSUR Repository.

왜 SPOR/IDMP인가: 제품·물질·조직·용어가 문서마다 자유 텍스트라 당국 간 연계(PV 신호·공급 부족·제조소 추적)가 안 됐다 → **ISO IDMP** 구조화 식별자. 팀엔 OMS 등록·RMS 용어·향후 PMS 제출 의무. **356h(PDF 서식) vs eAF(데이터 입력)** 차이가 두 지역의 구조화 전략 차이(EU는 신청서, 미국은 SPL·study data부터).

### 4.3 EU Module 1
**1.0** cover letter · **1.2** eAF · **1.3** product information(SmPC·라벨·PL, mock-ups, Braille, 가독성 검사) · **1.4** 전문가 정보 · **1.5** 특정 요건(10(1)·10a 등) · **1.6** ERA · **1.7** orphan · **1.8** PV 시스템 요약·RMP · **1.9** 임상시험 정보(제3국 윤리 진술) · **1.10** 소아(PIP compliance). **M2–M5는 공유, Module 1만 바꿔 끼운다** — 지역 사양·validation·요구 문서(미국 1.12.14 vs EU 1.6; 미국 특허 vs EU PIP)·sequence 이력은 지역별.

**Worksharing Type II(CAP 4개)**: 제품별 별도 sequence, 공통 문서는 각 sequence에 포함(또는 허용 범위 상호 참조), cover letter에 worksharing 번호·대표 제품, eAF는 PLM. 평가 1회, 결과는 각 MA에.

**505(b)(2) 문헌 의존**: 문헌 전문 **5.4**(비임상 4.3), bridging 논리 **2.5**(2.5.1)·2.7, 의존 진술 1.2/1.3, 참조 제품 특허 certification 1.3.5.

## 6. 21 CFR Part 11
| 조항 | 요건 |
|---|---|
| **11.10** | 폐쇄 시스템: 시스템 검증, 정확한 사본, 기록 보호, 접근 제한, **audit trail**(시간 기록·변경 이력), 운영 점검, 권한 확인, 교육 |

| **11.100–300** | 전자서명 일반·구성·ID/비밀번호; 사용 전 **11.100(c) 인증서**(non-repudiation letter) |

**2003 *Scope and Application***: 1997 Part 11이 모든 전자기록에 과도 적용돼 비용 폭증·전자화 저해 → **집행 재량**으로 범위 축소 — **predicate rule(211·312 등)이 요구하는 기록에만**, 검증·audit trail·보존·사본은 **위험 기반**. 규정 문구는 그대로, 기대치만 낮아져 전자 시스템 도입 가능(이후 데이터 무결성 가이드 보완). 미검증 e-signature 도구로 batch record·임상 문서 서명? predicate rule 기록이면 검증·audit trail·서명-기록 연결·고유 ID·서명 의미 표시·11.100(c) 제출이 필요 — 못 보이면 불가.

## 8. 흔한 혼동
1. **비eCTD NDA는 RTF?** 아니다 — "not received"(745A(a)).
2. **Research IND도 eCTD 의무?** 면제.
3. **High 오류 후 다음 sequence로 수정?** 같은 번호로 재제출.
4. **시판 후 ICSR을 eCTD로?** E2B(R3)→FAERS. 시판 후 의무는 2026-10-01(기준일 이후).
5. **PSUR을 CESP로?** PSUR Repository.
6. **v4.0이 의무?** 2026-09 기준 선택.
7. **STF는 EU도 필수?** FDA 요구, EU 선택.
8. **Part 11은 모든 전자기록?** predicate rule 기록, 위험 기반(2003).
9. **CBER는 다른 gateway?** 동일.

## 9. 네 분야에 올려놓기
첫 미국 IND(EV 제품) 3개월 전: **상업 IND는 eCTD 의무** → ESG NextGen 계정 지금; 공급자 **Type II·IV DMF도 2018-05-05부터 eCTD**, **Type III는 2019-05-05** — 비eCTD DMF면 참조가 막히니 계약으로 확인; GLP 독성은 **SEND** 데이터셋. 승인 후 1년 달력: annual report(1.13, 기념일 60일 내) · PMR/PMC 상태(506B) · periodic safety(314.80) · 라벨 변경 sequence(1.14 SPL) · 2253(1.15) · REMS 평가(1.16, 18개월) · CMC 변경(314.70/601.12) · drug listing(6월·12월) · establishment registration(10–12월) · PDUFA program fee — 각각 별도 sequence.
