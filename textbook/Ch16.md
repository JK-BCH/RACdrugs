# Ch.16 — 분석법 수명주기: "한 번 검증"에서 "설계·적격성·지속 검증"으로

> **덱:** Ch16 (20장).
> **검증 메모(2026-11-22):** ICH Q2(R2)+Q14 Step 4 2023-11(2025 오류정정판) — validation characteristics = accuracy·precision·specificity/selectivity·range, robustness는 Q14 개발 단계; ICH M10 2022 — Ch16 덱 메모 기준. USP <1220>/<1225>/<1226>/<1224>, FDA 2015 분석법 가이던스, 21 CFR 211.165(e)/211.194(a)(2)/211.160(b), 610.10·600.3(s), FDA Potency Tests CGT 2011, FDA 2004 변경 가이던스, EU B.II.d.2, EU GMP Ch.6은 ○ 안정 사실. "?": Ph. Eur. 5.26 장 번호. Potency Assurance 초안(2023-12)은 P2 ④ 덱 메모에 따르면 **2026-11-02 최종화 = 기준일 이후** → 시험엔 2011 가이던스 + 2023 초안 상태가 기준.

## 학습 목표
1. **Q2(R2)**(검증)와 **Q14**(개발)가 왜 한 쌍인지, **robustness가 어디에 속하는지** 말한다.
2. 시험 유형별로 **요구되는 검증 특성**을 배정한다.
3. **USP <1220>** 3단계와 **<1225>/<1226>/<1224>** 의 역할, **system suitability vs validation**을 구분한다.
4. 미국 법적 근거(**211.165(e)·211.194(a)(2)**)와 CTD 위치, 시판 후 분석법 변경 카테고리를 안다.
5. **M10**의 범위와 **potency assay(610.10)** 의 matrix approach를 설명한다.

## 1. Q14 + Q2(R2) — 분석법의 QbD

### 1.1 역할 분담
| | **Q14 (개발)** | **Q2(R2) (검증)** |
|---|---|---|
| 하는 일 | **ATP** 정의 → 이해 기반 설계 → **robustness 평가** → control strategy | 절차가 목적에 맞음을 **입증** |
| 검증 특성 | — | **accuracy · precision · specificity/selectivity · range(reportable range)** — linearity/response는 range 안에서 |
| robustness | **여기서**(개발 보고서에 문서화) | **반복할 필요 없음**(개발에서 했으면) |

QC가 "감사관이 기대하니 robustness를 검증 프로토콜에 넣자"고 하면: Q2(R2)는 robustness를 개발 활동으로 두므로, Q14 개발 보고서가 있으면 **그 보고서를 참조**하고 system suitability 기준으로 연결한다. 문서가 없으면 그때 개발 활동으로 수행해 개발 보고서에 넣는다 — 검증 항목이 아니다.

### 1.2 Minimal vs enhanced, ATP
- **Minimal**: 선행 지식·단변량 실험으로 절차를 정하고 Q2(R2) 검증 — 전통적 방식.
- **Enhanced**: **ATP**(analytical target profile — 측정 대상·목적·성능 기준을 사전 정의) → 체계적 개발(위험평가·DoE·파라미터 이해) → **control strategy** → 수명주기 관리.

### 1.3 왜 한 쌍인가 — Q12로 이어지는 유연성
구 Q2(R1)은 "검증 결과"만 다뤄 **왜 그 조건인지(개발 지식)** 가 dossier에 없었고, 그래서 사소한 변경도 당국 심사를 거쳤다. Q14가 개발 지식과 control strategy를 문서화하게 하고, 그 지식이 **Q12 established conditions**로 연결되면 **ATP 안에서의 변경은 낮은 카테고리나 PQS 관리**로 처리할 여지가 생긴다. QbD(Q8)의 분석법 판이다.

### 1.4 시험 유형별 검증 특성 (Q2(R2) 표)
| 시험 | 요구 특성 |
|---|---|
| **확인(identification)** | specificity/selectivity만 |
| **정량 불순물** | specificity + accuracy + precision(repeatability·intermediate) + range — 하한 **LOQ**(reporting threshold 커버) |
| **한도시험(limit test)** | specificity + 검출한계 |
| **정량(assay)** | specificity + accuracy + precision + range(보통 규격의 80–120%) |

## 2. 미국 약전·GMP 언어 — USP <1220>, <1225>/<1226>/<1224>, system suitability

### 2.1 USP <1220> (2022) 3단계
**Stage 1 Procedure Design**(ATP, 지식·위험 기반 개발, robustness) → **Stage 2 Procedure Performance Qualification**(= 검증, ATP 충족 입증) → **Stage 3 Ongoing Procedure Performance Verification**(일상 사용 중 성능 모니터링·추세, 변경 시 재평가). Q14/Q2(R2)와 같은 구조를 미국 약전 언어로 쓴 것.

### 2.2 Compendial 방법은 validation이 아니라 verification
- **<1225>** = compendial 절차의 **validation**(새 USP 절차를 만들 때, 또는 비공식법 검증 틀).
- **<1226>** = compendial 절차의 **verification**(기존 USP 방법을 자기 제품·조건에서 쓸 때 적합성 확인, 전체 검증 불요).
- GMP 근거: **211.194(a)(2)** 는 비공식 방법에만 검증을 요구하고, 공정서 방법은 **실제 사용 조건에서 적합함을 확인**하면 된다. **211.165(e)** 로 accuracy·sensitivity·specificity·reproducibility가 확립·문서화돼야 하는 건 공통.
- EU 대응: **EU GMP Chapter 6**(품질관리) + **Ph. Eur. 일반장 5.26**(공정서 절차의 이행 — 장 번호 확인 필요). 원칙은 <1226>과 같다.

### 2.3 System suitability ≠ validation
**System suitability**(211.160(b), USP <621>)는 **그날 그 시스템이 정상 작동**하는지 보는 run-level 점검이다. **Validation**은 절차 자체가 목적에 맞음을 입증하는 1회성(Stage 2) 활동이다. 수명주기에선 system suitability·추세 데이터가 **Stage 3 ongoing verification의 입력**이 되고, 반복 실패는 재검증·변경의 트리거다.

### 2.4 기술이전 — USP <1224>
① **comparative testing**(같은 시료를 양쪽에서 시험·비교) ② **co-validation**(검증에 수용 실험실 참여) ③ **revalidation** ④ **transfer waiver**(정당화 시). 프로토콜엔 책임·시료·기준물질·시험 설계·**사전 합격 기준**·일탈 처리·교육 기록. 생물검정은 비교 시험 + 정밀도 기준이 보통.

## 3. 미국 법적 근거와 CTD 위치
- GMP가 "검증됐고 문서화됐나"를 묻고(211.165(e), 211.194(a)(2)), 신청서(**314.50(d)(1), 601.2**)가 검증 데이터를 요구한다.
- CTD: 원료 **3.2.S.4.2/3.2.S.4.3**(절차·검증), 완제 **3.2.P.5.2/3.2.P.5.3**, 요약 **2.3 QOS**. EU·일본 동일(M4Q).

## 4. 시판 후 분석법 변경은 변경 관리다
| 변경 | 미국(314.70, FDA 2004 *Changes to an Approved NDA/ANDA*) | EU |
|---|---|---|
| 동등 입증된 방법 교체(HPLC→UPLC, 규격 불변) | **annual report 또는 CBE-30** | **B.II.d.2** — 사소·동등 **IA/IB**, 생물의약품·새 비표준법 **II** |
| 규격 완화·삭제(예: 용출시험 삭제) | **PAS** | **Type II**(B.II.d.1) |

"ATP가 critical이 아님을 보여준다"는 논리는 **정당화 근거**일 뿐 제출을 면제하지 않는다 — 규격은 Q12에서도 핵심 EC다. 미국은 **comparability protocol(314.70(e))** 로 사전 합의가 가능하고 Q12 ECs 개념도 수용된 반면, EU는 variation 분류가 법정(Reg 1234/2008)이라 Q12 유연성을 완전히 못 받는다(PACMP는 가능). 2026-01-15 적용된 새 Variations Guidelines가 일부 완화했지만 기본 구조는 같다.

## 5. 생체시료 분석 — M10 (2022)
**생체시료 중 약물·대사체 농도 측정**(PK/TK/BE용) 분석법 — **크로마토그래피법과 리간드 결합법**의 검증·시료 분석 요건을 통일. **바이오마커, 면역원성(ADA) 분석은 범위 밖**(별도 가이던스).

## 6. Potency — 610.10과 matrix approach
- 근거: **21 CFR 610.10**(생물의약품 역가 시험 필수) + **600.3(s)**(potency = 특정 결과를 낼 수 있는 능력, 실험실 시험으로 측정). **Q6B** 규격의 "생물활성" 항목이 바로 이것.
- 세포·EV 제품은 단일 역가 시험이 어려워 FDA *Potency Tests for CGT Products*(2011)의 **matrix approach** — 작용기전 관련 **생물학적 활성 시험**(예: 대식세포 표현형 전환 assay) + 대리 정량 시험(EV 수·마커)을 조합하고, 임상 단계별로 정량화·검증 수준을 높여 BLA 땐 Q2(R2) 검증 + Q6B 규격으로.
- **Q6B 규격** = 시험 목록 + 분석 절차 참조 + 합격 기준. 각 시험은 검증된(또는 적합성 확인된) 절차에 묶이고, 합격 기준은 임상·안정성 배치 경험으로 정당화.

## 7. 단계별 분석법 상태
| 시점 | 기대 |
|---|---|
| **IND/Phase 1** | 방법이 **목적에 적합(qualified)**; 안전성 관련 시험(무균·엔도톡신·확인·역가 대리)은 신뢰성 입증; 전체 검증 불요(FDA 2015, CGT CMC 가이던스) |
| **Phase 3 전** | pivotal 데이터·comparability를 뒷받침할 **핵심 시험 검증 완료**, 규격 잠정 확정 |
| **BLA** | **모든 출하·안정성 시험 Q2(R2) 검증**, Q14 수명주기 문서, 기준물질 확립 |

일정은 공정 lock과 맞물려 역산한다.

## 8. RTRT
RTRT = **공정 데이터(PAT)로 품질을 평가·보증**해 완제 시험을 대체(Q8(R2) 정의). NIR 모델은 Q2(R2)/Q14 다변량 절차 조항으로 검증·수명주기 관리, control strategy에 명시, EU **Annex 17**(RTRT·parametric release), 미국 PAT guidance(2004). RTRT는 규격의 일부라 승인 대상이고, 실패 시 전통 시험 fallback 규정이 필요.

## 10. 흔한 혼동
1. **Robustness는 검증 항목?** Q2(R2)에선 개발(Q14) 활동.
2. **USP 방법 쓰면 full validation?** verification(<1226>).
3. **System suitability 통과 = 검증?** run-level 점검일 뿐.
4. **동등한 방법으로 바꿨으니 제출 불요?** AR/CBE-30(미국), IA/IB(EU) — 비교 검증 데이터가 근거.
5. **ATP 논리로 규격 삭제를 변경관리로?** PAS/Type II.
6. **M10이 바이오마커도?** 아니다.
7. **Potency Assurance 최종판 인용?** 기준일 이후 — 2011 + 2023 초안.
8. **Q6A vs Q6B** — 생물의약품 규격은 Q6B.

## 11. 네 분야에 올려놓기
MSC-EV 제품의 potency는 **matrix approach**로 설계하고, Phase 1에선 qualified, Phase 3 전 핵심 시험 검증, BLA에서 전체 Q2(R2) 검증으로 간다. CDMO 이전은 <1224> comparative testing + 정밀도 기준. P2 ④(potency) 덱에서 이 장을 다시 쓴다.
