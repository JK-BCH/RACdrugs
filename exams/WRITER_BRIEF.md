# 문제은행 작성 에이전트용 공통 지시문

호출할 때 `<DECK>`(덱 id, 예: `Ch28_1`, `Ch20`, `P2_OTP`)와 장별 주의사항만 함께 준다. 아래를 그대로 따른다.

## 할 일
`D:\RAC\exams\bank_<DECK>.md`를 새로 쓴다. 64문항(Q01–Q64).

## 먼저 읽을 것(순서대로)
1. `D:\RAC\exams\AUTHORING.md` — 규칙 전부(0.5절 파일 단위 포함). 형식, 영문 지문·선지(한글 0), 한국어 해설(평서문, 규제 용어는 영어), 해설의 선지 글자는 `- B:` 글머리로만, 새 숫자 금지, 찍기 단서 금지, 기준일 2026-09-01(이후 사건은 "기준일 시점 비적용"으로만).
2. 사실 출처(이것만): 덱이 `ChNN`이면 `textbook\ChNN.md` + `cards\ChNN.md`. 덱이 `ChNN_1`/`ChNN_2`면 `textbook\ChNN.md` + `cards\ChNN_1.md` + `cards\ChNN_2.md`. 덱이 `P2_x`면 `textbook\P2_x.md` + `cards\P2_x.md`. 덱 검증 메모의 ✔/○는 사용 가능, "?"·"(확인 필요)"는 정답 키로 쓰지 않는다(오답 소재로만).
3. `D:\RAC\exams\bank_Ch05-06.md` — 완성본 예시. 8문항쯤 읽고 말투·오답 품질·선지 길이를 맞춘다.

## 범위
- `_1` 덱 = 1일차(개념·구조): `_1` 카드 주제와 교과서 "덱 카드와의 연결" 표에서 `_1`에 걸린 절 중심. 세부 다단계 시나리오는 `_2`에 양보.
- `_2` 덱 = 2일차(세부 규정·상황형): `_2` 카드 주제 중심, 적용·다단계 시나리오 위주.
- 한 사실을 여러 각도로(시나리오·참 고르기·틀린 것 고르기·교과서 규칙만 쓴 날짜·숫자 계산 — 계산은 두 번 검산).
- 2문장 이상 시나리오 지문 20문항 이상(`_2`는 25 이상). 유형 ≈ R 22 / A 32 / An 10. Domain I–V 고르게.

## 측정해서 맞춘다
- `D:/RAC/.venv/Scripts/python.exe D:/RAC/tools/bank_stats.py D:/RAC/exams/bank_<DECK>.md` → 정답=최장 10~30%, 정답=최단 ≤30%, 길이비 ≤1.10, 오답 절대어 ≤15가 될 때까지 고친다(정답 글자 분포는 나중에 스크립트가 맞춘다. 한 글자에 몰지만 말 것).
- `D:/RAC/.venv/Scripts/python.exe D:/RAC/tools/bank_numcheck.py` → `bank_<DECK>`에 걸린 숫자는 교과서 상수로 계산한 값이어야 한다. 아니면 지운다.
- `D:/RAC/.venv/Scripts/python.exe D:/RAC/tools/build_data.py` → 오류 없이 끝나고 bank=에 `<DECK>`가 나와야 한다.
- `bank_shuffle.py`는 돌리지 않는다. 다른 파일은 고치지 않는다(다른 에이전트가 교과서·덱을 고치는 중일 수 있다 — 읽기만).

## 머리말(bank_Ch05-06.md 형식)

## 쓰는 방법
Bash heredoc은 9KB를 넘으면 실패한다. Write 도구로 4조각(`D:\RAC\exams\_<DECK>.a`…`.d`, 각 16문항)을 쓰고 `cat`으로 합친 뒤 조각을 지운다.
